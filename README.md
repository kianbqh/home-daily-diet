# 今天想吃啥

把家里做过的菜记下来，再从菜品库里一起决定今天吃什么。

这是一个只给家庭成员使用的微信小程序：可以记录菜名和可选照片，追加同一道菜的制作记录，家庭成员从已有菜品中提交想吃的菜，并确认当天菜单。

## 当前版本

当前版本：`0.1.5`

本版本包含：

- 家庭成员通过短邀请码加入家庭。
- 家庭 ID 只在内部使用，不显示在页面、剪贴板或分享路径中。
- 邀请和家庭数据读写统一经过 CloudBase 云函数 `family-access` 校验微信用户身份。
- 本地数据与云端数据合并同步，连接失败时仍可继续使用本地数据。
- 菜品照片可选；照片上传失败时仍会保存菜名。
- 记录菜品页面不包含评价和备注板块。

已发布的 `0.1.5` 不包含聊天、公开菜谱社区、语音识别或 LLM 菜谱解析。

当前开发分支已经实现第二阶段代码与自动化回归：家庭主菜谱和本次做法版本、多段普通话录音、腾讯云异步转写、TokenHub 结构化草稿、人工确认、并发保护、费用限制及删除清理。它仍未部署到线上环境，也未完成双账号真机验收，因此不作为当前稳定版本宣传。

## CloudBase 配置

项目使用以下环境：

```text
AppID: wx6e247df29f902c68
环境 ID: home-daily-diet-d8f5e7d6907dd53a
区域: ap-shanghai
```

需要创建以下集合：

```text
family_states
family_states_events
family_members
family_invites
```

需要上传并部署云函数：

```text
cloudfunctions/family-access
```

建议部署顺序：

1. 在当前 CloudBase 环境创建四个集合。
2. 上传并部署 `family-access` 云函数。
3. 用微信开发者工具重新编译并真机测试。
4. 在家庭页生成邀请码，让其他家庭成员通过邀请码加入。

已有家庭第一次打开家庭页时，会自动完成当前微信用户与家庭成员的绑定。家庭成员不区分角色，默认可以记录菜品、提交选餐和同步家庭数据。

### 同步更新的重新部署与双账号验收

本次同步更新不需要新建集合；继续使用上面的四个集合。必须重新上传并部署 `family-access`，否则云端无法为家庭成员授权解析图片。

1. 在微信开发者工具中选择环境 `home-daily-diet-d8f5e7d6907dd53a`，右键 `cloudfunctions/family-access`，选择“上传并部署：云端安装依赖”。
2. 重新编译小程序；真机验收前，重新上传体验版。
3. 使用两个不同微信账号加入同一家庭。账号 B 先依次打开家庭页和包含指定菜品或制作记录的详情页，记录当前昵称、家庭名称和该图片，建立可见基线。
4. 账号 A 保存带唯一标识的昵称、家庭名称和该菜品或制作记录的精确图片，确认云端保存完成；等待超过 5 秒。
5. 账号 B 不下拉刷新，离开后返回家庭页和同一详情页，确认自动同步后的唯一昵称、家庭名称和精确图片。
6. 账号 B 保持在相关页面时，账号 A 再保存第二组不同的昵称、家庭名称和该精确图片，并确认云端保存完成。账号 B 分别在家庭页和同一详情页下拉刷新，确认强制同步后的新值和图片，且原生刷新动画结束。

## 本地开发与验证

在项目根目录运行：

```powershell
npm test
node scripts/smoke-check.js
```

自动化测试不会访问真实 ASR 或 TokenHub，也不会产生模型费用。`.env.example` 仅用于列出云函数环境变量名称，不能作为本地真实密钥文件使用。

### 脱敏模型评测

开发分支提供 Hy3 与 DeepSeek 的菜谱抽取评测工具。命令默认是 `dry-run`，只校验样例、模型白名单和报告结构，不访问 TokenHub，也不会产生模型费用：

```powershell
node scripts/evaluate-recipe-models.js --fixture tests/fixtures/recipe-transcripts.sample.json --models hy3,deepseek-v4-flash --dry-run --out $env:TEMP\recipe-eval.json
```

只有显式传入 `--live` 才会调用 TokenHub。实时评测需要单独配置 `TOKENHUB_API_KEY`，并在 Schema 成功率为 100%、未标记的不实精确事实为 0、关键事实召回率不低于 0.9 时通过上线门槛。

评分采用确定性的 `字段=事实` 编码，例如 `ingredient.name=鸡蛋`、`ingredient=鸡蛋|2个`、`step.heat=中火`、`step.duration=一分钟`。每个食材都单独记录名称事实；有明确用量时再记录“名称|用量”二元组，备注同样按“名称|备注”记录。这样只把用量标为不确定时，确定的食材名仍会参与幻觉检查。若对象级 `uncertain=true` 与具体 `uncertainties.fieldPath` 同时存在，具体路径优先；只有没有该对象的具体路径时，对象标记才作为整项不确定的兜底。二元组两部分自身的 `\`、`|` 分别写成 `\\`、`\|`，避免字段碰撞。`expectedFacts` 必须穷举样例支持的精确事实；模型输出中未标记为不确定、却不在该清单里的事实会计为不实精确事实，放错字段也会被识别。`forbiddenFacts` 用于额外标记明确禁用的事实，`*=180度` 表示该值无论落在哪个字段都禁止。比较前只做 Unicode 规范化、去除首尾空白、合并连续空白和英文小写化，不做模糊匹配。

召回率按所有样例的 `命中事实总数 / 预期事实总数` 计算，并使用未四舍五入的原值判断 0.9 门槛；报告中的小数只用于展示。字段准确率使用带字段事实集合的 Jaccard 比例，因此遗漏、额外事实和放错字段都会降低分数。

仓库只保留两条虚构、脱敏的普通话样例。真实家庭转写只能放在已忽略的 `tests/fixtures/private/`，不得提交到 Git。报告和常规控制台输出不包含完整转写或 API Key。

本地模式下，数据只保存在当前设备；连接 CloudBase 后才会跨设备同步。云端不可用时不会清空已有本地数据。

## 数据与隐私边界

- 家庭 ID 是内部标识，不作为用户邀请码展示。
- 邀请码由云函数生成、保存、过期和撤销。
- 云函数通过微信 `OPENID` 校验家庭成员关系。
- 项目不提供公开家庭内容、公开搜索或内置聊天。
- 第二阶段的五个菜谱集合设置为仅管理端可读写，小程序只能通过 `recipe-assistant` 访问。
- 原始语音保持私有；家庭成员播放和腾讯云 ASR 处理都使用短时 URL，URL 不落库、不进入日志或分享路径。
- 首版语音范围只有普通话 `16k_zh`，不尝试识别温州话，也不提供方言选择。
- AI 只生成待确认草稿，不能自动覆盖正式菜谱；如果人工切换 TokenHub 下游模型，必须同步更新隐私说明。
- 当前版本尚未完成小程序备案和生产级运营体系，不应当作面向公众的产品使用。
