# 今天想吃啥

> 把家里做过的菜留下来，今天吃什么不再从头想。

“今天想吃啥”是一个面向家庭的微信小程序。它先把家里做过的菜、照片和制作经验积累成菜品库，再让家人从已有菜品中选择今天想吃什么，减少反复询问，也不再忘记那些曾经做得很好吃的菜。

当前仓库版本：`0.3.0`（开发预览）

## 为什么做这个小程序

很多家庭都会遇到相似的问题：会做的菜其实不少，但每天临时问“吃什么”时，大家还是只能想起最常见的几道。过去做得很好吃的菜没有被记录，做法和小技巧也会慢慢忘记。

这个项目把顺序固定下来：

```text
先记录家里的菜 → 菜品进入家庭菜品库 → 家人一起点菜 → 继续补充每次制作的经验
```

## 现在可以做什么

| 能力 | 说明 |
| --- | --- |
| 家庭空间 | 通过 6 位短邀请码邀请家人，家庭名称、成员称呼和共享数据可跨设备同步 |
| 家庭菜品库 | 记录菜名、可选照片、分类标签和特点；支持搜索、筛选、编辑与回收站 |
| 制作记录 | 同一道菜可保留多次制作日期、餐次和照片，不覆盖过去的记录 |
| 一起点菜 | 家人从菜品库提交想吃的菜，再确认一餐的最终菜单 |
| 家人评价 | 针对某一次制作给出 0.5 至 5 星评价和文字内容，在菜品详情中集中查看 |
| 家庭菜谱 | 手动填写或用普通话语音整理菜谱，记录食材、步骤、技巧、失败经验和家庭经验 |
| 历史与恢复 | 保留本次做法、家庭主菜谱和只读历史版本；误删菜品可以从回收站恢复 |

## 一次完整的使用流程

1. 第一次打开时创建家庭空间，并用短邀请码邀请家人。
2. 吃饭时拍一张照片、记录菜名，让它进入家庭菜品库；没有照片也可以保存。
3. 家人从菜品库选择今天想吃的菜，共同确认这一餐的菜单。
4. 做完后为同一道菜追加本次制作记录、照片和评价。
5. 手动填写做法，或口述家里的经验，再把确认后的内容保存为家庭菜谱。

菜品必须先进入菜品库，之后才能被选择为“今天想吃什么”。小程序不会在点菜页面临时创建菜品，也没有内置聊天功能。

## 家庭菜谱助手

家庭菜谱助手用于把家人口述的做菜经验整理成以后可以复刻的内容：

```text
普通话录音或文字补充
→ 人工检查转写
→ AI 整理为结构化草稿
→ 家人修改并确认
→ 保存本次做法，必要时更新家庭主菜谱
```

- 支持多段普通话录音，每段独立上传和转写。
- 也可以完全跳过录音，只用文字填写菜谱。
- AI 只整理来源中出现的信息，缺失内容会留空或标记为不确定。
- AI 结果始终是待确认草稿，不能自动覆盖正式菜谱。
- 每次确认会生成不可变版本，旧版本仍可只读查看。

首版语音只按普通话处理，不尝试识别温州话，也不提供方言选择。

## 当前状态与边界

`0.3.0` 包含家庭空间、菜品库、点菜、制作记录、评价、回收站，以及手动和语音菜谱整理的完整源码与自动化测试。

发布门槛状态：`待执行`

这是一个需要自行部署的开发预览，并不是已经备案和运营的公开服务。准备真实使用前，部署者仍需完成自己的 CloudBase 环境、微信小程序隐私声明与备案配置，并按照双账号真机验收表检查跨成员同步、录音、转写、AI 整理、版本冲突和删除生命周期。

项目当前不包含：

- 内置聊天或群机器人。
- 公开菜谱社区、陌生人搜索或跨家庭推荐。
- 方言识别、实时字幕或自动切换大模型。
- 营养分析、采购清单、支付或外卖能力。
- 家庭管理员、复杂角色权限或运营后台。

## 运行自己的版本

### 准备工作

- 微信开发者工具。
- 一个微信小程序 AppID。
- 一个腾讯云 CloudBase 环境。
- Node.js 20，用于运行本地测试和云函数。
- 可选的腾讯云录音文件识别与 TokenHub Key；不配置时仍可使用基础功能和手动菜谱。

### 导入项目

1. 克隆仓库，并在微信开发者工具中导入仓库根目录。
2. 把 `project.config.json` 中的 `appid` 改成自己的小程序 AppID。
3. 把 `cloudbase.config.js` 中的 `envId` 改成自己的 CloudBase 环境 ID。
4. 创建下方集合，部署 `family-access` 与 `recipe-assistant` 云函数。
5. 只在云函数控制台配置真实 Key；不要把凭据写入 `.env.example`、小程序代码或 Git。

完整权限、索引、环境变量、预算告警、隐私与回滚步骤见[第二阶段 CloudBase 部署清单](docs/cloudbase-phase-two-setup.md)。

## 本地验证

```powershell
npm test
node scripts/smoke-check.js
```

自动化测试使用假服务，不会访问真实 ASR 或 TokenHub，也不会产生模型费用。

如果需要比较 Hy3 与 DeepSeek 的结构化菜谱能力，可以运行默认不联网、不计费的脱敏评测：

```powershell
node scripts/evaluate-recipe-models.js --fixture tests/fixtures/recipe-transcripts.sample.json --models hy3,deepseek-v4-flash --dry-run --out $env:TEMP\recipe-eval.json
```

只有显式传入 `--live` 才会调用 TokenHub。真实家庭转写只能放在已忽略的 `tests/fixtures/private/`，不能提交到仓库。

## 数据与隐私

- 家庭 ID 是内部标识，不显示为邀请码，也不进入分享路径。
- 云函数通过微信 `OPENID` 与家庭成员关系进行授权。
- 家庭图片与原始语音保持私有，只向有权限的家庭成员返回短时访问地址。
- 日志不记录完整语音、转写、菜谱正文、Key、OpenID 或短时 URL。
- 云端不可用时，基础数据继续保存在当前设备；恢复连接后可以重新同步。
- AI 只生成草稿，正式菜谱必须由家庭成员确认。
