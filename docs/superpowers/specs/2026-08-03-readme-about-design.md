# README 与 GitHub About 主页设计

**日期：** 2026-08-03  
**目标仓库：** `kianbqh/home-daily-diet`  
**目标版本：** 0.1.1 文档整理

## 1. 目标

把仓库首页从“开发配置记录”调整为兼顾产品理解和开发运行的项目主页：第一次访问的人能快速明白“今天想吃啥”解决什么问题，开发者也能在后半部分找到运行、CloudBase 配置和验证方法。

本次只调整项目文档和 GitHub 仓库元数据，不改小程序运行逻辑、不新增产品功能。

## 2. README 结构

README 按以下顺序组织：

1. **标题与一句话定位**
   - 产品名称“今天想吃啥”。
   - 强调家庭菜品记忆与共同选餐。

2. **为什么做它**
   - 家里做过的好菜容易被遗忘。
   - 每天反复沟通“吃什么”成本高。
   - 菜品库先记录，菜单再选择。

3. **使用流程**
   - 记录家里的菜。
   - 家人从菜品库选择想吃的菜。
   - 确认当天菜单并分享给家人。
   - 吃完后继续补充制作记录。

4. **当前能力**
   - 家庭空间和成员邀请。
   - 菜品库、可选图片和历史制作记录。
   - 多人提交当天想吃的菜。
   - CloudBase 云端同步，连接失败时保留本地可用性。
   - 第一版不包含内置聊天、公开社区和 LLM 菜谱解析。

5. **项目状态**
   - 标明当前为 0.1.1。
   - 用短列表说明本版本修复内容。
   - 不宣称已经备案、正式商用或具备完整家庭权限隔离。

6. **开发者说明**
   - 技术栈、AppID、CloudBase 环境与集合名称。
   - 本地运行和验证命令。
   - CloudBase 创建、绑定和集合权限注意事项。
   - 指向 `SPEC.md` 的详细需求文档。

7. **边界与后续方向**
   - 明确当前版本的隐私和客户端直连限制。
   - 简要列出后续语音、原始语音保留和 LLM 结构化菜谱方向，不把它们写成已完成能力。

不加入虚构截图、虚构演示链接、营销式口号或与当前代码不一致的功能描述。
