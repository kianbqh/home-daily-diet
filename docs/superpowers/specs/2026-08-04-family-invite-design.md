# 家庭邀请码与成员授权重构设计

**日期：** 2026-08-04  
**目标版本：** 0.1.5  
**项目：** 今天想吃啥微信小程序

## 1. 背景与目标

当前客户端把 `family.id` 同时当作家庭内部标识和邀请码，并在家庭页面直接展示。客户端还可以直接使用家庭 ID 读取和保存 CloudBase 数据。这样既造成用户界面出现一串不可读的 ID，也无法让服务端确认“当前微信用户是否属于这个家庭”。

本次重构直接建立正式邀请机制：家庭 ID 只作为服务端和本地状态的内部字段；用户使用短邀请码加入家庭；所有云端读写通过云函数校验微信用户身份和家庭成员关系。同时修复云端初始化覆盖本地数据的问题，保证小程序在云端暂时不可用时仍然可以使用本地数据。

本次不实现家庭角色、管理员体系、聊天、公开分享或复杂的邀请权限。家庭成员默认拥有相同的记录、选餐和同步权限。

## 2. 方案与边界

采用单个 `family-access` 云函数承载邀请和家庭数据访问，使用动作参数区分操作。这样比在客户端继续拼接家庭 ID 更安全，也比立即拆分多个云函数更适合当前小程序规模。

现有 `family_states` 与 `family_states_events` 集合继续保存家庭快照和事件，避免迁移已有菜品与选餐数据。新增 `family_members` 和 `family_invites` 两个集合，服务端通过调用上下文中的 `OPENID` 校验成员身份。

已有家庭首次调用云端授权接口时，如果该家庭尚无成员绑定，当前微信用户被绑定为初始成员。这是针对当前私有家庭应用的迁移策略；后续若扩展到更多家庭，再增加管理员转移和更严格的初始化凭证。

## 3. 数据结构

### 3.1 `family_members`

每条记录代表一个微信用户在一个家庭中的成员关系：

```text
{
  _id: "familyId|memberId",
  familyId: string,
  memberId: string,
  openid: string,
  displayName: string,
  joinedAt: ISO datetime,
  updatedAt: ISO datetime,
  status: "active"
}
```

`openid` 只在云函数和受控数据中使用，不返回到小程序页面。`memberId` 继续沿用客户端家庭状态中的成员 ID，保证现有成员记录能够延续。

### 3.2 `family_invites`

每个家庭最多保留一个有效邀请码：

```text
{
  _id: string,
  familyId: string,
  code: string,
  createdBy: string,
  createdAt: ISO datetime,
  expiresAt: ISO datetime,
  revokedAt: ISO datetime | "",
  status: "active" | "revoked" | "expired",
  useCount: number
}
```

邀请码为 6 位大写字母和数字，排除 `0/O`、`1/I` 等易混淆字符。有效期为创建后 30 天；重新生成会立即撤销旧码。服务端每次使用时检查状态和有效期，并在成功加入后递增 `useCount`。

## 4. 云函数接口

云函数名称：`family-access`。所有动作从调用上下文读取 `OPENID`，客户端不能传入或覆盖调用者身份。

### `bootstrap`

用于已有家庭第一次绑定当前用户。输入 `familyId`、`memberId` 和 `displayName`。若家庭没有成员关系，则创建初始成员；若已有关系，则只返回当前用户的成员信息。

### `createInvite`

输入 `familyId`。服务端确认调用者是 active 成员后，返回当前有效邀请码；没有有效邀请码时生成新的邀请码。

### `getInvite`

输入 `familyId`。仅 active 成员可调用，返回当前有效邀请码和有效期；没有邀请码时返回空结果，不返回家庭内部 ID 给页面。

### `revokeInvite`

输入 `familyId`。撤销当前邀请码，不删除家庭数据。

### `acceptInvite`

输入短邀请码、客户端当前成员 ID 和称呼。服务端查找有效邀请码，创建或更新 `family_members` 记录，将成员写入家庭快照，并返回经过授权的家庭状态。客户端只使用返回结果切换到目标家庭，不再调用 `load(familyId)`。

### `load` 与 `save`

两者都输入 `familyId`，但服务端先用 `family_members` 校验当前 `OPENID` 是否为 active 成员，再读取或合并 `family_states` 与 `family_states_events`。客户端保留家庭 ID 作为内部参数，但不在任何用户界面、剪贴板内容或分享路径中展示。

`save` 使用现有的按实体 ID 合并规则：成员、菜品、制作记录、饭局和选餐记录分别合并；确认过的饭局不能被未确认状态覆盖。服务端只保存去掉 `currentMemberId` 的共享状态。

## 5. 客户端改动

### 5.1 `services/cloudbase-sync.js`

- 增加云函数调用封装和错误码转换。
- `load`、`save`、`joinFamily` 改为调用 `family-access`。
- 增加 `createInvite`、`getInvite`、`revokeInvite`、`acceptInvite`。
- 云函数失败时返回可识别的错误类型，不吞掉过期、撤销、无权限等具体原因。
- 图片上传继续使用现有 CloudBase Storage 路径，但路径只在内部生成，不放入分享链接。

### 5.2 `services/app-store.js`

- 增加本地待同步状态标记和串行同步队列。
- 云端 hydration 使用 `mergeFamilyStates(remote, local)`，不再直接用远端状态替换本地状态。
- hydration 期间发生的本地提交进入队列，完成后再次保存合并结果。
- `joinFamilyByInvite` 通过邀请码接受云函数返回的授权状态。
- `getFamilySummary` 只提供家庭名称、成员数量和同步状态；不提供供页面直接渲染的家庭 ID。

### 5.3 家庭页面

- 显示 6 位邀请码，不显示完整 `family.id`。
- 支持复制、重新生成和撤销邀请码。
- 分享路径只携带邀请码：`/pages/family/family?inviteCode=XXXXXX`。
- 本地模式隐藏邀请操作，显示“连接云端后可邀请家人”。
- 加入失败时分别提示邀请码无效、已过期、已撤销、无云端连接或权限校验失败。
- “家庭成员”文案统一为“共 N 位家庭成员”，避免出现缺少数字的句式。

### 5.4 其他页面

- 首页、选餐页和菜品库订阅 store 的同步更新，云端 hydration 完成后自动刷新。
- 所有分享路径移除裸 `familyId`，需要加入家庭时统一使用邀请码。
- 保持记录菜品不包含评价和备注输入；图片上传失败时允许只保存菜名。

## 6. 同步与错误处理

本地数据始终先保存，再尝试同步。云端同步失败不会清空本地状态，页面显示同步错误并允许继续使用。成功恢复连接后，队列按顺序将本地变更与云端合并保存。

若加入家庭成功但客户端保存失败，客户端优先使用云函数返回的授权状态，并将后续保存加入同步队列。若邀请码已失效，客户端不重复重试，提示用户让家庭成员重新生成邀请码。

函数端对非法动作、缺少参数、非成员访问、无效邀请码和过期邀请码返回稳定错误码；客户端统一映射为中文提示，避免把 `familyId`、`openid` 或数据库错误栈显示给用户。

## 7. 测试与验收

### 单元测试

- 生成的邀请码长度、字符集和排除字符符合要求。
- 邀请码创建、获取、撤销、过期和重新生成行为正确。
- 非成员不能读取或保存家庭数据。
- 接受邀请码后只创建一个成员关系，重复接受不会重复添加成员。
- hydration 合并远端数据、本地数据和 hydration 期间的新提交。
- 家庭页面 view model 不暴露完整家庭 ID，页面只显示短邀请码或云端不可用提示。

### 本地回归

- `npm test`
- JavaScript 语法检查
- 构建资源检查和现有 smoke test
- 家庭名称、成员称呼输入可见且不会被同步刷新覆盖
- 无图片记录菜品可以保存

### 真机验收

1. 创建或恢复家庭后生成邀请码。
2. 另一台微信使用邀请码加入，双方都能看到家庭成员和菜品。
3. 撤销旧邀请码后，旧码无法加入；重新生成的新码可以加入。
4. 页面任何位置都不出现长家庭 ID。
5. 断开云端后已有数据仍可浏览和编辑，恢复连接后数据不丢失。

## 8. 不在本次范围

- 家庭管理员、成员移除和权限分级。
- 聊天、通知和邀请码使用次数上限。
- 数据库历史事件的压缩归档。
- 生产环境备案、隐私协议和正式发布流程。
