# 第二阶段：语音家庭菜谱助手设计

**状态：** 已确认
**日期：** 2026-08-13
**适用项目：** 今天想吃啥（微信小程序）

## 1. 目标

第二阶段把家人做菜时口述的经验，沉淀为以后可以复刻的家庭菜谱。

核心流程固定为：

```text
追加制作记录
→ 录制一段或多段普通话语音
→ 每段上传并异步转写
→ 家人校对转写
→ 主动点击“整理成菜谱”
→ AI 生成结构化草稿
→ 家人修改并确认
→ 保存本次做法，必要时更新家庭主菜谱
```

任何语音转写或 AI 结果都只是草稿。未经家庭成员确认，不得覆盖已经保存的菜谱。

## 2. 已确认的产品决策

- 采用“家庭主菜谱 + 每次制作做法”的两层结构。
- 每道菜最多有一份当前生效的家庭主菜谱，但保留历史版本。
- 每次制作可以保存一份独立的、已经确认的本次做法。
- 若菜品尚无主菜谱，首次确认的本次做法自动成为主菜谱。
- 若已有主菜谱，默认只保存本次做法；“同时更新主菜谱”默认关闭。
- 支持连续录制多段语音，每段最长 3 分钟。
- 首版只支持普通话，不提供方言选择，也不尝试识别温州话。
- 每段录音停止后立即上传并进入后台转写，不必等待上一段完成。
- 录音全部完成后，由用户主动点击一次“整理成菜谱”，不在每段录音后调用大模型。
- 原始语音和原始转写长期保留；转写文本可以人工修改。
- 即使语音或 AI 不可用，也可以完整手动填写并保存菜谱。
- 家庭成员不区分角色，都可以查看、修改和确认草稿。
- 主菜谱每次确认更新都生成新版本；首版可以查看旧版本，但不做复杂差异对比和一键回滚。
- 继续维持每次制作最多一张成品照片；首版不增加步骤图片、视频或多图。

## 3. 首版范围边界

### 3.1 包含

- 现有菜品详情页中的家庭菜谱入口。
- 现有“追加新记录”中的制作过程录入。
- 多段普通话录音、播放、上传、删除和状态显示。
- 腾讯云普通话录音文件识别。
- 原始转写、人工修订文本和纯文字补充。
- TokenHub 结构化菜谱整理。
- AI 不确定内容标记。
- 草稿自动保存、人工编辑和确认。
- 本次做法、当前主菜谱和主菜谱历史版本。
- 跨家庭成员查看、编辑与确认。
- 乐观并发控制、幂等调用和费用保护。

### 3.2 不包含

- 方言识别或自动语言判断。
- 边说边出字的实时转写。
- 内置聊天、AI 问答或公开菜谱社区。
- AI 自动修改正式菜谱。
- 视频、步骤配图和多张过程图片。
- 营养分析、采购清单或根据库存推荐。
- 主菜谱版本差异比较和一键回滚。
- 自动在 Hy3、DeepSeek、Kimi 之间切换。
- 新增单条历史制作记录的删除入口；若未来增加，必须遵守本文的数据清理规则。

## 4. 信息结构与页面

### 4.1 菜品详情页

在菜品摘要之后增加“家庭菜谱”卡片：

- 没有菜谱时显示“还没有记录做法”和“手动创建菜谱”。
- 有菜谱时显示食材数量、步骤数量、最后更新人和时间。
- 点击进入完整菜谱页。
- 主菜谱卡片只展示当前版本，不在详情页直接编辑长表单。

每条制作记录增加对应状态：

- `暂无做法`
- `语音转写中`
- `菜谱草稿待确认`
- `已保存本次做法`

已确认的记录提供“查看本次做法”；未完成的记录提供“继续整理”。

### 4.2 追加新记录

用户点击现有“追加新记录”按钮后，展开两个部分。

“本次记录”保持现有字段：

- 制作日期
- 餐次
- 一张可选成品照片

新增“制作过程”：

- 开始/结束录音按钮，不要求持续按住。
- 当前录音时长和 3 分钟倒计时。
- 多段录音列表。
- 每段的播放、转写状态、修改文字、重试和删除。
- “添加文字说明”入口，用于不录音或补充遗漏。
- 所有可用文本就绪后显示“整理成菜谱”。

为避免录音先上传、制作记录后生成而无法关联，打开追加表单时预留稳定的 `recordId`。保存制作记录时沿用该 ID；取消追加时清理尚未提交的录音工作区。

现有领域层需要允许 `addCookingRecord(input)` 接收调用方预生成的 `input.id`。首次保存使用该 ID；相同 ID 的重复提交必须幂等返回已有记录，若菜品或关键字段不一致则拒绝，不能创建第二条制作记录。

首次创建菜品仍保持当前简洁流程。保存菜品后，可进入详情页通过“追加新记录”记录完整制作过程，首版不在首次建菜页面内同时引入语音工作区。

### 4.3 菜谱草稿确认页

独立页面 `pages/recipe-draft/recipe-draft`，包含：

- 原始语音列表，可播放。
- 原始转写和人工修订文本。
- 食材与用量。
- 制作步骤。
- 火候和时间描述。
- 技巧。
- 常见失败问题、原因和补救方式。
- 家庭经验。
- AI 不确定项提示。
- “仅保存本次做法”或“同时更新主菜谱”。

未确认草稿在停止输入约 800 毫秒后自动保存，页面明确显示“保存中／已保存／保存冲突”。点击“确认保存”才生成不可变的正式版本。

从制作记录进入时显示两个保存选项。若当前没有主菜谱，页面明确提示“本次确认将同时建立家庭主菜谱”；若已经有主菜谱，“同时更新主菜谱”默认关闭。从“手动创建菜谱”或“编辑主菜谱”进入时，确认操作只生成新的主菜谱版本，不显示“仅保存本次做法”。

### 4.4 完整菜谱页

独立页面 `pages/recipe/recipe`：

- 展示当前家庭主菜谱。
- 支持“编辑主菜谱”，以当前版本复制出新草稿。
- 展示最后确认人和时间。
- 展示历史主菜谱版本列表。
- 旧版本只读，不提供差异对比和回滚。

## 5. 菜谱数据结构

结构化内容不强制标准单位，保留家常表达：

```js
{
  ingredients: [
    {
      name: '鸡蛋',
      amountText: '3 个',
      note: '',
      uncertain: false,
    },
    {
      name: '盐',
      amountText: '少许',
      note: '最后尝味再加',
      uncertain: false,
    },
  ],
  steps: [
    {
      order: 1,
      instruction: '鸡蛋打散后先炒至刚凝固，盛出备用',
      heat: '中大火',
      durationText: '',
      keyPoint: '不要炒老',
      uncertain: false,
    },
  ],
  tips: ['番茄出汁少时可以加一点水'],
  failures: [
    {
      problem: '鸡蛋发老',
      cause: '第一次炒得太久',
      remedy: '刚凝固就盛出',
    },
  ],
  familyNotes: ['妈妈习惯最后放一点糖'],
  uncertainties: [
    {
      fieldPath: 'ingredients[1].amountText',
      message: '原话没有给出精确用量，请确认',
    },
  ],
}
```

“适量”“少许”“一勺左右”“看情况”等表达保持原样。AI 不得擅自转换成克数，也不得补写原始内容中不存在的食材、温度或时长。

## 6. CloudBase 架构

现有 `family_states`、`family_states_events`、`family_members` 和 `family_invites` 保持不变。第二阶段新增云函数 `recipe-assistant`、四个业务数据集合和一个用量集合。

### 6.1 `recipe_recordings`

每段语音或纯文字片段一条记录：

```text
_id
familyId
dishId
recordId
sequence
sourceType             audio | manual_text
fileId
durationMs
format
byteLength
status                 reserved | uploading | transcribing | ready | failed
asrTaskId

asrSubmittedAt
asrExpiresAt

```

`_id` 是本系统生成的全局唯一 ID。腾讯 ASR 的 `TaskId` 有有效期且可能跨日期重复，不能作为业务主键。

### 6.2 `recipe_drafts`

```text

sourceRecordingIds
sourceType             recording | manual | edit_main
status                 editing | organizing | ready | failed | confirmed
recipe                  结构化菜谱内容

confirmedVersionId
```

### 6.3 `family_recipes`

每个家庭内每道菜一条当前指针：

```text
_id                    familyId|dishId
familyId
dishId
currentVersionId
currentVersionNumber
createdAt
updatedBy
updatedAt
```

### 6.4 `recipe_versions`

确认后不可变：

```text
_id
familyId
dishId
recordId
versionNumber
recipe
sourceDraftId
publishedAsMain        创建时是否发布为主菜谱
previousMainVersionId
confirmedBy
confirmedAt
```

`recordId` 可以为空：从某次制作整理时关联该次记录，直接编辑主菜谱时为空。每次确认都生成一条正式版本；关联制作记录的版本同时是该次做法。没有主菜谱时，新版本自动发布为主版本；已有主菜谱时，只有用户开启“同时更新主菜谱”才更新 `family_recipes.currentVersionId`。

`publishedAsMain` 只表示该版本创建时曾被发布为主菜谱，不表示它现在仍是最新版。当前生效版本始终以 `family_recipes.currentVersionId` 为准，因此历史版本本身无需修改。

`versionNumber` 在同一家庭与同一道菜内单调递增。确认操作在事务中完成版本号分配、版本创建、草稿状态更新和主菜谱指针更新；同一 `draftId + revision` 重复确认时直接返回已有 `confirmedVersionId`，不得生成重复版本。

### 6.5 `recipe_usage_daily`

按家庭和自然日原子记录费用额度：

```text
_id                    familyId|YYYY-MM-DD
familyId
date
reservedAsrSeconds
completedAsrSeconds
organizeCalls
updatedAt
```

提交 ASR 前先按单段上限预留额度，提交失败时释放；完成后按实际时长核销。AI 整理调用也在请求发出前原子计数，避免多个家庭成员同时操作绕过限制。腾讯云控制台仍需另外设置账号级预算和告警，应用内额度不是账单保护的唯一措施。

## 7. 云函数边界与动作

`recipe-assistant` 负责所有敏感操作：

- `reserveRecording`：校验家庭成员和费用限制，预留录音 ID 与上传路径。
- `submitRecording`：验证上传结果，生成短时文件访问地址并提交 ASR。
- `attachRecordWorkspace`：保存制作记录后，把预留工作区标记为正式关联状态。
- `cancelRecordWorkspace`：取消追加记录并幂等清理尚未关联的片段、草稿和音频。
- `refreshWorkspace`：批量查询尚未完成的 ASR 任务并更新状态。
- `updateTranscript`：保存人工修改文本，使用 `transcriptRevision` 防覆盖。
- `addManualText`：创建纯文字片段。
- `deleteRecordingAudio`：删除原始音频，但保留转写及已确认菜谱。
- `deleteRecording`：删除尚未确认的片段和对应音频。
- `getRecordWorkspace`：读取某次制作的片段和草稿。
- `organizeDraft`：调用 TokenHub 并保存结构化草稿。
- `updateDraft`：保存人工修订，使用 `revision` 防覆盖。
- `confirmDraft`：创建不可变版本，必要时事务更新主菜谱指针。
- `getRecipe`、`listVersions`、`getVersion`：读取正式菜谱。
- `createManualDraft`：无语音时创建或编辑菜谱。
- `purgeDishArtifacts`：菜品彻底删除后的幂等清理。

所有动作从 `getWXContext()` 获取 `OPENID`，再通过 `family_members` 校验当前用户是否属于该家庭。客户端提交的 `familyId`、`memberId` 或文件路径都不能单独作为授权依据。读取或变更菜谱时还要验证 `dishId` 属于该家庭且未被彻底删除；涉及制作记录时验证或最终核对 `recordId` 与 `dishId` 的关联。

`reserveRecording` 只返回形如 `families/<familyId>/recipe-audio/<recordingId>.mp3` 的一次性预留路径。`submitRecording` 只接受预留文档中完全相同的 CloudBase 文件 ID，并校验格式和不超过 5 MB 的文件大小，拒绝任意客户端路径。

五个新增集合均设置为客户端不可直接读写，只允许云函数使用服务端权限访问。音频读取由 `getRecordWorkspace` 返回短时地址；短时地址过期后重新请求，不由客户端直接枚举云存储。

## 8. 录音与转写

### 8.1 客户端录音

- 使用微信小程序 `RecorderManager`。
- MP3、16 kHz、单声道，以控制文件大小并匹配普通话识别。
- 每段 180 秒自动停止。
- 单次制作最多 10 段，累计最长 15 分钟。
- 录音停止后先保存本地临时副本，再上传 CloudBase。
- 上传成功后删除可恢复的本地副本；上传失败时保留并允许重试。
- 预留录音时按 180 秒占用当日额度，识别完成后再按实际时长核销，避免伪造客户端时长绕过费用限制。

### 8.2 ASR 服务

- 使用腾讯云“录音文件识别”异步接口，而不是最多 60 秒的“一句话识别”。
- 固定引擎 `16k_zh`，只识别普通话和少量英文，不启用方言模型。
- 通过 CloudBase 短时签名 URL 提交私有音频，不把存储桶改为公开读。
- 页面打开时查询未完成任务；用户离开页面不影响腾讯云继续识别。
- ASR `TaskId` 仅在 24 小时内用于查询。过期或查询失败时保留音频，允许重新提交。
- 不启用说话人分离、情绪识别、口语转书面语等额外收费能力。

## 9. AI 菜谱整理

### 9.1 服务选择

- 通过腾讯云 TokenHub 的 OpenAI 兼容接口统一接入。
- 默认模型为 `hy3`。
- 环境变量允许改为 `deepseek-v4-flash` 进行评测或人工切换。
- 首版不接 Kimi，也不自动调用第二个模型兜底。
- 默认关闭深度思考；本任务是结构化抽取，不需要高成本推理。

环境变量：

```text
TOKENHUB_API_KEY
RECIPE_MODEL=hy3
RECIPE_PROMPT_VERSION=v1
ASR_SECRET_ID
ASR_SECRET_KEY
ASR_REGION=ap-shanghai
ASR_ENGINE=16k_zh
```

腾讯云权限允许时，ASR 优先使用最小权限的运行角色临时凭证；不具备角色凭证时才使用云函数环境中的密钥。任何密钥都不能进入小程序包、Git 仓库或日志。

### 9.2 输出约束

- 使用 TokenHub 的结构化输出能力和固定 JSON Schema。
- 输入转写被视为数据，提示词明确禁止执行转写文本中的指令。
- 模型只能整理来源中明确出现的信息。
- 信息缺失时留空并写入 `uncertainties`，不能自行补齐。
- 所有转写和手动补充合计最多 30,000 个字符，超过时拒绝整理并提示精简。
- 服务端对输出做字段、长度、数组数量和类型校验：最多 50 项食材、30 个步骤、20 条技巧、20 条失败经验和 20 条家庭经验；单个说明字段最多 1,000 个字符，完整结构化菜谱最多 100 KB。
- 仅在 JSON 格式不合法时自动修复重试一次；内容问题不自动重复调用。
- 保存 `modelName`、`promptVersion`、请求 ID 和 token 用量，但日志不记录完整转写或菜谱正文。

### 9.3 逻辑异步任务

点击“整理成菜谱”后，先把草稿状态写成 `organizing`，云函数再等待 TokenHub 返回并更新为 `ready` 或 `failed`。用户可以离开页面；再次进入时读取集合中的最终状态。

若任务长时间停留在 `organizing`，页面允许重新发起。`inputHash` 和幂等键保证同一份输入不会并发产生重复版本或重复计费。

## 10. 协作与版本控制

- 所有家庭成员具有相同菜谱权限。
- 页面显示录音者、最后修改人和确认人。
- 草稿更新必须携带读取时的 `revision`。
- 服务端只在版本一致时更新并递增 `revision`。
- 版本冲突返回 `DRAFT_CONFLICT`，客户端保留本地编辑内容，并提示先刷新后重新应用修改。
- 确认主菜谱时携带 `baseMainVersionId`。
- 若期间主菜谱已被别人更新，返回 `MAIN_RECIPE_CONFLICT`，不得静默覆盖。
- 正式 `recipe_versions` 不再原地修改；后续编辑总是生成新版本。

## 11. 删除与保留规则

- 原始语音默认随制作记录长期保留。
- 用户可单独删除一段原始语音；对应转写和已确认菜谱保留，并标记 `audioDeletedAt`。
- “只删除原始语音”仅在转写已经完成或已有人工文本时开放；转写中的片段只能整体移除，后续 ASR 结果必须被忽略。
- 删除尚未确认的整个片段时，同时删除音频和该片段转写。
- 取消尚未保存的追加记录时，立即清理本次临时工作区。
- 异常退出留下的未绑定工作区保存 7 天，并在后续云函数调用中机会式清理。
- 菜品移入回收站只隐藏，不删除菜谱、语音或版本。
- 菜品彻底删除后，先以现有 `purgedDishes` 墓碑阻止读取，再幂等清理四个业务数据集合和 CloudBase 音频文件；按日用量审计记录不删除。
- 若未来增加单条制作记录的彻底删除，必须同时清理其语音、转写、草稿和仅属于该记录的本次做法版本；已经被提升为主菜谱的版本必须先生成独立主版本快照再清理。

## 12. 错误处理与降级

- **麦克风未授权：** 说明用途并提供打开设置；始终保留文字录入入口。
- **录音被系统中断：** 有有效临时文件时保留该片段，否则提示重新录制。
- **上传失败：** 保留本地副本和文字内容，允许重试，不创建 ASR 任务。
- **转写失败或过期：** 保留原始语音，允许重新转写或改为手动输入。
- **部分片段仍在转写：** 禁用“整理成菜谱”，明确列出未完成片段。
- **AI 调用失败：** 保留所有转写和已编辑草稿，允许重试或完全手动整理。
- **ASR 或 AI 服务未开通：** 手动菜谱仍可用；手动模式绕过两项外部服务，但共享保存仍需要 CloudBase 在线。
- **模型输出不合法：** 最多自动修复一次；仍失败则进入可恢复失败状态。
- **云端不可用：** 现有记录、点菜和评价功能继续可用；菜谱助手明确显示需要联网。
- **并发冲突：** 不自动合并长表单，不覆盖较新内容。
- **菜品已彻底删除：** 所有菜谱动作返回 `DISH_PURGED`，并触发机会式清理。

## 13. 隐私与安全

- 首次使用录音前展示用途说明，并遵守微信麦克风权限与隐私协议要求。
- 隐私说明明确原始语音会上传到家庭私有云空间，并交由腾讯云语音识别处理。
- 如果部署者把模型切换为第三方模型，隐私说明必须同步披露 TokenHub 下游模型提供方；因此生产环境不自动切换模型。
- 音频文件保持私有，只通过短时 URL 交给 ASR 和授权家庭成员播放。
- 临时 URL 不落库、不写日志、不进入分享路径。
- 云函数只返回当前家庭有权读取的数据。
- 日志记录错误码、请求 ID、耗时和用量，不记录完整音频、转写或菜谱正文。

## 14. 成本保护与预估

服务端限制：

- 每段最长 3 分钟。
- 每次制作最多 10 段、总计最多 15 分钟。
- 每个录音同一时间最多一个 ASR 任务。
- 每个草稿同一时间最多一个 AI 整理任务。
- 每个家庭每天最多转写 60 分钟、整理菜谱 20 次；达到上限后次日恢复。
- 相同 `inputHash` 复用已有结果，不重复调用模型。
- 腾讯云控制台配置月度预算和费用告警；达到服务端硬限制时直接拒绝新任务，不进行隐式后付费重试。

按 2026-08-13 官方刊例价粗略估算：

- 普通录音文件识别后付费约 1.75 元/小时；3 分钟满额约 0.088 元。
- Hy3 输入约 1 元/百万 token、输出约 4 元/百万 token。
- 假设一次整理输入 2,000 token、输出 1,000 token，模型费用约 0.006 元。
- 家庭场景的主要可变费用是语音时长，模型整理费用通常远低于 ASR 和文件存储费用。

价格可能变化，部署前以腾讯云控制台为准，不把价格写入运行逻辑。

## 15. 测试与验收

### 15.1 自动化测试

- 数据模型：本次做法、主菜谱指针和不可变版本。
- 首次确认自动创建主菜谱；已有主菜谱默认不更新。
- 草稿与主菜谱乐观锁冲突。
- 录音状态机和 3 分钟自动结束。
- 多段录音排序、文字补充和转写修订。
- ASR 任务提交、查询、过期、失败和幂等重试。
- TokenHub JSON Schema 校验、一次格式修复和失败降级。
- 不确定项不得被静默写成确定事实。
- 家庭成员鉴权和跨家庭拒绝。
- 音频短时 URL 与删除生命周期。
- 回收站保留和彻底删除清理。
- 并发提交下的每日用量原子预留、核销和释放。
- 页面离开后重新进入可恢复状态。
- 现有菜品、评价、点菜和家庭同步全量回归测试。

ASR 与 TokenHub 通过适配器注入，单元测试使用假服务，不在普通测试中产生真实费用。

### 15.2 真实语料评测

准备至少 20 段真实普通话做菜口述，同时用 Hy3 和 DeepSeek-V4-Flash 整理同一批转写。按以下顺序决定默认模型：

1. 未经来源支持却新增的食材、用量、温度或步骤数量。
2. 来源关键信息召回率。
3. 字段归类正确率。
4. JSON Schema 成功率。
5. 平均响应时间。
6. 单次费用。

上线门槛：

- 经过最多一次格式修复后，结构化输出成功率 100%。
- 测试集中不得出现未标记的不实精确用量、温度或时长。
- 来源关键事实进入正确字段的比例不低于 90%。
- 所有失败路径都能保留原始语音或人工文本，并允许手动完成。

### 15.3 双账号真机验收

1. 账号 A 追加制作记录并连续录制两段语音。
2. A 在第一段转写期间继续录制第二段，然后离开页面。
3. A 再次进入，看到两段最终状态并修改其中一段转写。
4. A 整理菜谱并离开，稍后重新进入查看草稿。
5. 账号 B 查看同一草稿、修改并确认。
6. A 看到 B 确认的本次做法和主菜谱版本。
7. A、B 同时编辑，旧版本保存被阻止且内容不丢失。
8. 删除单段音频后，转写和菜谱仍存在。
9. 菜品移入回收站后数据保留；恢复后可继续查看。
10. 菜品彻底删除后，所有成员都无法再读取菜谱或音频。

## 16. 交付里程碑

### 里程碑 1：手动菜谱与版本基础

- 新集合与 `recipe-assistant` 鉴权骨架。
- 手动创建菜谱草稿。
- 草稿编辑、确认、本次做法和主菜谱版本。
- 菜品详情与完整菜谱页面。
- 不接 ASR 和 TokenHub，先验证数据结构与跨设备协作。

### 里程碑 2：录音与普通话转写

- 录音 UI、本地恢复、CloudBase 上传与播放。
- `16k_zh` 录音文件识别。
- 多段状态、人工纠错、重试和单段语音删除。
- 不接 AI，用户可把转写手动整理为菜谱。

### 里程碑 3：AI 整理与确认闭环

- TokenHub 适配器与 Hy3 默认模型。
- 结构化输出、AI 不确定项和格式校验。
- 后台整理状态、失败恢复和人工确认。
- Hy3 与 DeepSeek 的真实语料对比。

### 里程碑 4：上线加固

- 并发冲突、幂等、费用限制和机会式清理。
- 回收站与彻底删除生命周期。
- 双账号真机验收、隐私说明和部署文档。
- 全量回归、云函数日志和费用监控。

每个里程碑都必须保持现有基础功能可用，并可单独发布和回退。
