# 统一家庭菜谱工作台设计

## 背景

第二阶段的录音、普通话转写、AI 整理、人工确认和版本保存已经分别存在于代码中，但入口被拆成了两条互不解释的路径：

- “家庭菜谱 → 手动创建菜谱”直接进入长表单，没有语音入口。
- “追加新记录”才挂载录音工作区，而且录音位于一组低优先级字段之后。

这使用户很容易把“没有看到录音按钮”理解为功能没有实现。草稿页同时重复系统标题、展开所有空白区块，首屏缺少明确主操作。

## 目标

让普通用户无需理解“主菜谱”“制作记录”“草稿”等内部概念，也能完成以下闭环：

1. 从菜品详情一眼看到语音入口。
2. 追加一次制作记录后立即口述一段或多段普通话。
3. 查看上传和转写状态，校对文字或补充纯文字。
4. 主动点击“整理成菜谱”。
5. 在紧凑的结构化编辑器中检查结果并确认。
6. 保存为本次做法，并按现有规则选择是否更新家庭主菜谱。

手动填写必须始终可用，并在 ASR 或 AI 不可用时作为完整降级路径。

## 方案选择

采用“统一入口、保持两类数据语义”的方案，不把没有制作记录的手动主菜谱强行伪装成一次制作记录。

- 语音入口创建或恢复一次临时制作记录工作区，沿用现有 `recordId`、录音上传、转写、草稿和确认链路。
- 手动入口继续创建不带 `recordId` 的主菜谱草稿。
- 两条路径在菜品详情的同一张“家庭菜谱”卡片中并列呈现，语音为主按钮，手动为次按钮。
- 手动草稿页提供醒目的“改用语音记录”入口，返回原菜品详情并直接展开录音工作区；已输入的手动草稿保留，不静默删除。

不新增集合，不改变已有正式版本结构，也不允许 AI 结果绕过人工确认。

## 页面与交互

### 菜品详情

没有家庭主菜谱时，卡片展示：

- 主按钮：“语音记录做法”，带麦克风标识。
- 次按钮：“直接手动填写”。
- 简短说明：“适合边做边说，之后会整理成可编辑草稿。”

已经有主菜谱时，“查看完整菜谱”保持不变；“追加新记录”仍是记录下一次制作的入口。

点击语音入口后：

- 展开本次记录区域。
- 录音工作区排在菜名、图片、日期和餐次之前。
- 页面滚动到录音卡片。
- 可选图片、日期和餐次收进“补充本次信息”，默认收起；保存前仍沿用当前默认日期和餐次规则。

### 录音工作区

首屏展示一个清晰的录音卡：

- 标题：“说说这次怎么做”。
- 辅助文案：“可以分几段说，停下来后会自动上传并转成文字。”
- 主操作：“开始录音”；录制中切换为红色“结束录音”。
- 显示已录时长和三分钟倒计时。

首次点击录音前展示用途说明：录音用于生成文字和家庭菜谱，会上传到家庭私有云空间并由腾讯云语音识别处理。用户确认后才请求麦克风；拒绝时保留文字说明入口。

每段内容继续保留播放、重新上传/转写、删除和人工修订。所有片段就绪后只显示一个主要动作“智能整理成菜谱”。

### 手动/AI 草稿页

- 使用系统导航标题，不再重复大型页面标题和英文眉题。
- 顶部只保留紧凑状态条：手动草稿、整理中、待确认、失败或已保存。
- 手动草稿顶部显示“改用语音记录”次级入口。
- 食材、步骤、技巧、失败经验和家庭经验以紧凑卡片呈现。
- 空区块只占一行：标题、简短说明和小型“+ 添加”按钮，不保留大块空白。
- 有内容的区块展开字段；确认保存按钮保持底部清晰可见。
- AI 不确定项、来源转写、冲突恢复和版本确认逻辑保持不变。

## 数据流

语音路径沿用现有流程：

```text
菜品详情打开临时制作记录
→ recipe-recording-workspace 录音
→ reserveRecording / CloudBase upload / submitRecording
→ refreshWorkspace 得到普通话转写
→ 用户修订或补充文字
→ organizeDraft
→ recipe-draft 页面检查并确认
→ attachRecordWorkspace 后保存制作记录
```

手动路径仍为：

```text
createManualDraft(sourceType=manual)
→ recipe-draft 手动编辑
→ confirmDraft(publishAsMain=true)
```

## 错误与降级

- 设备不支持录音：显示原因和文字说明入口。
- 麦克风拒绝：不自动重复请求，提示可在设置中开启，同时保留文字录入。
- 上传或转写失败：保留本地音频并提供重试；不得阻塞基础菜品和评价功能。
- AI 未配置或调用失败：保留转写，允许直接手动整理和确认。
- 从手动草稿切换到语音：保留手动草稿，不删除、不覆盖。
- 页面离开再返回：恢复临时录音、云端片段、转写和草稿状态。

## 验收标准

自动化必须证明：

- 菜品详情同时呈现语音主入口和手动次入口。
- 语音入口会展开记录工作区并定位到录音卡。
- 录音组件中存在可见的开始/结束按钮和首次用途确认逻辑。
- 手动草稿页存在返回语音工作区的入口。
- 草稿页不再重复页面标题，五个空区块使用紧凑样式。
- 原有录音、转写、AI 整理、冲突、版本、删除和费用限制测试继续通过。

真机验收必须证明：

- iOS 和至少另一台微信客户端都能从菜品详情在两次点击内开始录音。
- 首次用途说明和系统麦克风授权顺序正确。
- 连录两段、转写期间继续录制、离页恢复、人工修订、AI 整理、确认和跨成员查看形成完整闭环。
- ASR/AI 缺失时手动路径仍可完成菜谱。
- 页面在常见窄屏上没有标题换行、按钮溢出或大面积无意义空白。

## 非目标

- 不支持温州话或其他方言模式。
- 不加入聊天、公开社区、自动发布或模型自动切换。
- 不让未确认的转写或 AI 草稿覆盖家庭主菜谱。
- 不为纯手动主菜谱创建虚假的制作记录。
